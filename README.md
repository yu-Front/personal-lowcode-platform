# 个人低代码平台

一个可直接运行和公开演示的轻量低代码平台作品。项目完整覆盖：

`数据对象 → 页面 DSL → 服务 → 流程编排 → 发布快照 → 运行态 → 人工审批`

数据全部保存在浏览器 IndexedDB，不需要服务器、数据库账号或付费云资源。

## 功能

- 数据对象：字段新增、编辑、删除，支持文本、数字、金额、日期、枚举与布尔类型。
- 本地账号：注册时选择初始身份，支持登录、退出和会话恢复；密码使用 PBKDF2 派生后保存。
- 权限管理：管理员可为其他账号添加或移除多个身份、删除账号；权限按账号聚合，不需要在账号内切换身份。
- 应用中心：新建、切换和删除多个独立应用，支持采购模板与空白应用；每份工作空间带所属应用 ID，异步加载、编辑和保存均执行应用隔离校验。
- 页面设计：组件面板、响应式画布和属性面板，配置保存为 JSON DSL。
- 服务中心：对象 CRUD 与 Mock 服务配置、响应编辑和在线测试。
- 流程设计：开始节点绑定触发页面与按钮；审批节点绑定任务页面，并可配置同意流向、退回上一步、退回发起人、指定节点或结束流程；条件和服务节点支持独立分支流向。
- 发布中心：依赖校验、不可变发布快照、版本记录、JSON 导入导出与示例恢复。
- 运行态：采购申请列表、动态表单、账号级权限、待办审批和流程轨迹。
- 审批规则：部门经理同意后，金额大于 10,000 元进入财务审批，否则直接结束。

## 本地运行

建议 Node.js 20：

```bash
npm install
npm run dev
```

默认地址：<http://localhost:4173>

演示账号：`demo@forge.local` / `demo123`

## 测试和构建

```bash

npm run build
npm run preview
```

## 演示路径

1. 使用管理员演示账号登录，或注册一个只属于当前浏览器的新账号并选择初始身份。
2. 在“应用中心”新建模板应用或空白应用，并体验应用切换。
3. 在“数据对象”查看采购申请字段。
4. 在“页面设计”添加组件、修改绑定并保存。
5. 在“流程设计”查看金额条件和审批角色。
6. 在“发布中心”发布一个版本。
7. 进入运行态；拥有申请人身份的账号可以发起金额超过 10,000 元的采购申请。
8. 拥有部门经理或财务审批人身份的账号可在“我的待办”中处理对应审批；管理员可在“用户管理”中调整其他账号的身份。
9. 在“流程轨迹”查看完整审计记录。

## GitHub Pages 部署

项目内置 `.github/workflows/deploy-pages.yml`。将本目录作为独立仓库推送到 GitHub 后：

1. 项目使用相对资源路径与 HashRouter，仓库名称可自由选择。
2. 在仓库 `Settings → Pages → Build and deployment` 中选择 `GitHub Actions`。
3. 推送到 `main` 后，Actions 会自动测试、构建并部署。

GitHub Pages 是静态托管；IndexedDB 数据仅保存在每位访客自己的浏览器中，互不共享。这非常适合作品演示，但不适合作为多人共用的生产数据库。

## 架构说明

- `src/data/indexedDb.ts`：浏览器本地持久化仓储。
- `src/state/PlatformContext.tsx`：本地账号、会话与多应用管理。
- `src/state/WorkspaceContext.tsx`：配置态与运行态统一状态服务。
- `src/domain/workflowEngine.js`：可独立测试的流程规则。
- `src/types/workspace.ts`：对象、页面、服务、流程、发布与运行数据模型。
- `src/pages`：各工作台与运行态页面。

代码为清洁实现，仅借鉴通用低代码产品的分层思想，不包含原公司源码、接口、名称或内部素材。
